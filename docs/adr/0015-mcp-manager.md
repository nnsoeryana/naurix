# ADR 0015 — MCP manager: registry, secrets, approval, test, sync (M7)
**Status:** Accepted

**Context:** Users should manage MCP servers without hand-editing JSON, with secrets kept safe and user configuration never damaged. M6 established that only Claude Code (project `.mcp.json`) and OpenCode (flat `mcp.<name>`) have a *verified* config format.

**Decisions**
1. **Registry** in SQLite (`mcp_servers`, migration 2): definition templates only. A `${secret:NAME}` placeholder may appear in arguments, environment values and header values; every placeholder must be declared, every declaration used, and any other `${…}` is rejected (it would depend on the user's shell). A schema test forbids columns that could hold values.
2. **Secrets live only in the macOS Keychain** (`security-framework`, service `dev.naurix.app.mcp`, account `<server id>:<NAME>`). The UI can set, replace and remove a value; **no command ever returns one**. Plain-text credentials are refused up front: secret-looking env names and header names (`KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `AUTH`…) must use a placeholder, and passwords embedded in URLs or connection strings are rejected. A test scans every byte SQLite writes (database, WAL, shm) for a known secret value.
3. **Agent config files contain references, not values.** Claude: `${NAURIX_MCP_<SERVER>_<NAME>}`; OpenCode: `{env:NAURIX_MCP_<SERVER>_<NAME>}`. Both expansions were **verified with the real CLIs** in `env`/`args`/`headers` (fixtures README). When Naurix launches an agent whose MCP handling is verified, it adds those variables from the Keychain to the agent's environment. Consequence, stated in the UI: **agents started outside Naurix's Agents panel do not receive the secrets** (verified: the server then gets the literal reference text plus a warning from Claude, never the value). Plain shell tabs deliberately do not receive secrets.
4. **Approval is bound to a SHA-256 fingerprint** of what would run (transport, command, args, URL, environment/header templates, secret names). The review dialog shows the exact command; "Approve" sends the fingerprint that was displayed, so a server edited in between cannot be approved by mistake. Editing anything that runs invalidates approval; renaming or changing a secret's value does not. Both **Test connection** and **sync** require approval; new servers start enabled but unapproved. npx/uvx-style commands get an explicit "downloads and runs a package" warning.
5. **Test connection** (stdio only) starts the approved command with an argument array in its own process group, speaks MCP (`initialize` with protocol `2025-06-18`, `notifications/initialized`, paged `tools/list`), caps sizes and time, and kills the whole group afterwards (tested: a child the server spawned does not survive). Interoperability was checked against a real server (`claude mcp serve`) and a scripted one. **Remote (HTTP) servers are reported as "not testable"** instead of faked: that needs an HTTP/TLS client and OAuth, which are out of scope.
6. **Sync engine** (`mcp::sync`): plan (pure, no writes) → user reviews → apply → undo. Rules: only verified agents; write only entries Naurix created; **never overwrite or remove an entry it did not write or that the user edited since** (ownership recorded as a hash per entry); preserve every other key and the user's key order; refuse files that are not plain JSON (comments → shown as a snippet to add by hand, never rewritten); refuse OpenCode's unverified `mcp.servers` layout; the plan hash binds *Apply* to what was reviewed (a changed file means "review again"); atomic write after a backup (`<data dir>/mcp-backups`); undo restores the exact original bytes, deletes a file the run created, restores ownership rows, only for the newest run, and only if the file is exactly as the run left it.
7. **Catalog** (6 entries, no marketplace): Filesystem, GitHub (remote, PAT as a secret), PostgreSQL (**flagged: archived upstream on 2025-05-29**, connection string as a secret), Playwright, Context7 (remote; optional key explained, not preset), Sentry (remote, OAuth by the agent). Commands, URLs and header formats were read from each project's own documentation on 2026-11-19; the source link is shown. Context7's local npx command is not in its README, so it is not offered.

**Not done / limits:** user- and local-scope Claude config (`~/.claude.json`), Codex/Gemini/Antigravity sync (documented only), OpenCode project-level and `mcp.servers` files, OAuth, testing remote servers, and bulk import of servers already configured in agents. Real-world behaviour of the third-party catalog packages (e.g. `npx` downloads) was **not** executed during development (supply-chain risk); only the scripted and Claude servers were.
