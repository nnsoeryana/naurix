# ADR 0017 — Read-only Git status, hardened against hostile repositories (M9)
**Status:** Accepted (implements ADR 0005)

**Context:** The product shows branch, changed files and basic state (GIT-001/002/004/007, diff GIT-003 and worktree list GIT-005 as P1) without becoming a Git client. Running `git status` in a folder is not harmless: Git runs programs named in the repository's own configuration (`core.fsmonitor`), external diff drivers, textconv filters and clean filters. AGENTS.md forbids executing commands that come from project files.

**Decisions**
1. **Shell out to the installed `git`** with an argument array (no shell). Commands used: `rev-parse --show-toplevel --absolute-git-dir`, `status --porcelain=v2 -z --branch --show-stash --untracked-files=normal --ignore-submodules=dirty`, `diff` (bounded), `worktree list --porcelain -z`, `config --local --list`. **Nothing writes**: there is no commit, stage, checkout, stash or reset.
2. **Hardening on every call:** `--no-optional-locks` (never take the index lock, so Naurix cannot make the user's own `git` fail; tested with a held lock and an unchanged index mtime), and command-line overrides that outrank the repository's config: `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `core.pager=cat`, `diff.external=`, `credential.helper=`, `core.untrackedCache=false`; diffs add `--no-ext-diff --no-textconv`; `GIT_DIR`/`GIT_WORK_TREE`/`GIT_EXTERNAL_DIFF`/`GIT_SSH*`/`GIT_ASKPASS` are removed from the environment; no prompts.
3. **The one vector that cannot be switched off per call is clean filters** (`filter.<name>.clean/smudge/process`, which `git status` runs for attributed files) and `include.path`/`includeIf` (which can pull in more config). Before running anything else, Naurix reads the repository's **local** config only and, if it defines those keys, returns **Blocked** and does not run Git there until the user explicitly trusts that repository (remembered per repository). Filters defined in the user's own global config (for example Git LFS) do not trigger this, so normal LFS repositories are unaffected.
4. **Tested with hostile repositories:** a repository configured with a malicious `core.fsmonitor`, `diff.external`, `core.pager` and a `textconv` driver. A naive `git status`/`git diff` creates the marker files (checked in the test, so it is meaningful); Naurix's calls do not. A repository defining a clean filter is blocked and its marker is never created.
5. **Bounds:** status output 8 MB / 20 s timeout; at most 2000 file entries (counts stay exact, with a "truncated" flag); diff output 512 KB with lines shortened to 2000 characters; binary files reported as such; diff paths validated (relative, no `..`, not starting with `-`, passed after `--`).
6. **Refresh policy (GIT-004), no polling, no file watcher:** status is fetched when a workspace is selected, when the Git view opens, when the window regains focus, when a terminal or agent session ends, and on the Refresh button. Requests are coalesced (one in flight, one queued). The footer shows the branch and a dirty count from the same result.
7. **"Open repository in terminal" (GIT-007):** the webview sends only a flag; the backend resolves the repository root itself and starts the shell there (verified: a workspace in a subfolder opens a terminal at the repository root). The webview can never name a directory.
8. **Information shown:** branch or detached HEAD, upstream with ahead/behind, stash count, merge/rebase/cherry-pick/revert/bisect in progress, conflicts, staged, unstaged and untracked files (a file with both staged and unstaged changes is listed in both), renames, submodule marks, linked worktrees.

**Verified** against real repositories: all change kinds, awkward file names (spaces, Unicode, newline, quotes), detached HEAD, a repository with no commits, stash, ahead/behind against a real upstream, merge and rebase conflicts, a bare repository, a workspace inside a subfolder, linked worktrees, 2050 files, and the full UI flow (including a change made from outside being picked up when the window regains focus).

**Limits:** untracked directories are shown as a directory entry (`dir/`), not expanded; diffs of a directory are not offered; very large monorepos may exceed the 20 s status limit (reported as a clear error); `.gitattributes` conversions are Git's own; `git` must be installed (Xcode command line tools provide it) and a repository owned by another user is reported by Git as unsafe rather than overridden.
