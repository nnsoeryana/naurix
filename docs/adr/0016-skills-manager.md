# ADR 0016 — Skills manager: central store, symlink links, untrusted content (M8)
**Status:** Accepted

**Context:** Agents read skills from folders (`~/.claude/skills`, `.agents/skills`, `~/.config/opencode/skills`, …) per their documentation (docs/AGENT_ADAPTERS.md). Unlike MCP, there is no account-free way to confirm that an agent *discovers* a skill. The maintainer decided (2026-11-19) that a **reversible symlink into the documented folder is acceptable without a live discovery test**.

**Decisions**
1. **New verification level `DocumentedAccepted`** (ADR 0014 addendum): documented, not confirmed, and acted on **only** through a reversible symlink. `acts_on` is true for it; it is shown as "Link only, not verified" in the launcher and everywhere else. A test pins which agents have it (Claude Code, Codex, Antigravity, OpenCode; not Gemini CLI) and asserts that no skills fact is `Verified`.
2. **Skills are untrusted.** Nothing inside a skill is ever executed by Naurix: sources are fetched, inspected, copied and linked. A test installs, links, updates and uninstalls a skill containing a shell script, a Python script, a JS file and `!`command`` injection, and asserts the marker those would create does not exist; the same was observed in the real app.
3. **Sources:** a local folder (one skill, or a folder of skills; `SKILL.md` searched to depth 3) or an **https** Git URL. Git fetch = `git clone --depth 1` into a staging folder with hooks disabled (`core.hooksPath=/dev/null`), `core.symlinks=false` (repository symlinks arrive as plain files), no submodules, `GIT_ALLOW_PROTOCOL=https`, credential helper off, no prompts, 120 s timeout; URLs with credentials or other schemes are refused. Local-path clones exist only behind a test-only switch.
4. **Review before install** shows source (URL @ commit, or folder), the store location, file count/size, every script-like file, and risk flags: shell-injection syntax, pre-approved shell tools, hooks, scripts, binaries, skipped symlinks. Compatibility per agent comes from the documented requirements (Codex requires `name` + `description`; OpenCode advertises only skills with a description; Antigravity's are unknown). The hash the user saw is checked again at install; if the files changed, nothing is installed.
5. **Central store** `<data>/skills/<id>/rev-<hash>/` plus a stable `current` symlink; the copy contains regular files only (symlinks never followed or copied), limited to 2000 files / 5 MB per file / 20 MB total. Agent folders link to `<id>/current`, so **updating re-points `current` atomically** and every link keeps working. The previous revision is kept; *Switch to previous version* toggles between the two (older ones are pruned).
6. **Links:** created only where the path does not exist (a file, folder or foreign symlink there blocks and is reported, never replaced); removed only if the path is still a symlink to Naurix's `current`; a folder Naurix had to create is removed again when it becomes empty. Agents sharing a folder (Codex and Antigravity project `.agents/skills`; OpenCode also reads `~/.claude/skills` and `~/.agents/skills`) are shown honestly rather than duplicated.
7. **Update** is user-initiated only (no background network): git re-clones to staging, shows added/changed/removed files and **newly introduced risk flags**, and applies only the reviewed hash. **Uninstall** (confirmed) removes Naurix's links, its stored copy and its record; a link the user replaced is left alone and reported; the original source is never touched.
8. **Persistence:** `skills` and `skill_links` (migration 3) hold metadata only; content stays on disk. Front matter is read by a small tolerant parser (plain, quoted, `|`/`>` scalars; only top-level scalars).

**Verified:** against the real public repository `anthropics/skills` (20 skills found, 12 flagged for scripts or commands) and with the real UI creating the symlink chain `project/.claude|.agents|.opencode/skills/<name> → <data>/skills/<id>/current → rev-…` and removing it again, with the user's real `~/.claude/skills` untouched.

**Not verified / limits:** that any agent follows a symlinked skill folder and loads the skill (Codex's docs say it follows symlinks; the others are silent); skills in `~/.claude.json`-style plugins or marketplaces; SSH/private repositories; Gemini CLI skills; the "category" browsing (SK-008, P1).

**Addendum — built-in skills:** skills can ship inside the app (`crates/core/resources/skills/<slug>/SKILL.md`, embedded with `include_str!`; currently `natural-writing`). At startup each is copied **once** into the central store as source kind `builtin` (`builtin:<slug>`), the same way any reviewed skill is. Seeding **never creates agent links**: the user still enables it per agent. A `skills.builtin_seeded.<slug>` setting records the seed, so a skill the user uninstalls is not added back. "Check for updates" compares against the embedded copy, so a newer app version delivers an updated skill through the normal reviewed update flow. Test: `builtin_skill_is_seeded_once_unlinked_and_not_readded_after_uninstall`.
